# WB Tracker – Документация для ИИ-ассистента (Claude / Cursor)

## Контекст проекта
Это backend-сервис на **FastAPI**, который выступает в роли трекера данных с Wildberries (аналог Xway для рекламы и Indipa для цен). Сервис автоматически и по расписанию собирает данные по рекламным кампаниям и ценам конкурентов/своих товаров через официальное API Wildberries, сохраняя историю изменений (снапшоты) в PostgreSQL.

**Главная фишка:** Мы записываем каждое изменение ставки, бюджета, статуса кампании, а также цены и скидок СПП. На основе изменения цен и заложенной себестоимости автоматически рассчитывается **маржинальность**.

## Стек технологий
- **Backend:** Python 3.12+, FastAPI, Uvicorn
- **База данных:** PostgreSQL (развернута на платформе Render)
- **СУБД драйвер:** `asyncpg` (полностью асинхронное взаимодействие)
- **Фоновые задачи:** `APScheduler` (cron/interval внутри единого процесса FastAPI)
- **HTTP Клиент:** `httpx`

## Решенные проблемы с WB API (Март 2026)
Важно при написании нового кода учитывать актуальное состояние API Wildberries:
1. Эндпоинт `POST /adv/v1/promotion/adverts` **удален**. Для получения списка всех кампаний и их ставок используется **`GET /api/advert/v2/adverts`**. Ставки возвращаются в копейках `bids_kopecks.search`.
2. Эндпоинты цен `card.wb.ru` защищены или не отдают нужные данные. Используется **официальный Seller API**: `https://discounts-prices-api.wildberries.ru/api/v2/list/goods/filter`.
3. Типы кампаний (campaign_type) теперь могут прилетать как строки (`manual`, `unified`), а не INT. В базе они сейчас сохраняются как NULL, а строковый тип пишется прямиком в `name` кампании.

## Структура Базы Данных (PostgreSQL)
Все миграции лежат в `migrations/001_initial.sql`.

1. **`products`**
   - Товары для отслеживания (задаются через `PRODUCT_ARTICLES` в .env).
   - Поля unit-экономики: `cost_price` (себестоимость), `wb_commission` (комиссия ВБ в %), `logistics_cost` (стоимость логистики).
2. **`campaigns`**
   - Уникальные рекламные кампании.
3. **`campaign_snapshots`**
   - Исторические срезы кампаний. Каждые 15 минут, если ставка/бюджет/статус изменились, пишется новая строка (`is_changed=true`).
4. **`price_history`**
   - Снапшоты цен. Содержит: `price_base`, `price_sale`, `price_spp`, `discount_percent`, `spp_percent`.
5. **`margin_calculations`**
   - Расчет маржи. Высчитывается автоматически коллектором цен, если у товара заполнена `cost_price`. Хранит `revenue`, `gross_profit`, `margin_pct`.
6. **`campaign_daily_stats`**
   - Суточная статистика трат и кликов (views, clicks, spend) по кампаниям.

## Что нужно сделать Клоду (Immediate Next Steps)

Твоя задача — построить вокруг этого бэкенда мощный и удобный дашборд.

### 1. Доделать API (Backend)
- Добавить роуты для Unit-экономики (`GET /products` и `PUT /products/{wb_article}`). Пользователь должен иметь возможность обновлять `cost_price`, `wb_commission`, `logistics_cost` для расчета маржи.
- Подключить эндпоинт `GET /api/v1/warehouse` (WB API) для получения остатков на складах и написать новый коллектор `app/collectors/inventory.py`.

### 2. Frontend Dashboard (React / Next.js)
Создать интерфейс (рекомендуется Next.js + Tailwind CSS + Recharts для графиков):
- **Dashboard (как у Xway):**
  - Таблица активных кампаний с их текущей ставкой `bid` и бюджетом.
  - Лента изменений ставок (используй `/changes` из бэкенда).
- **Price & Margin (как у Indipa):**
  - График истории цен (базовая → со скидкой → с СПП).
  - Вывод текущей **маржи** (брать из `margin_calculations`).
- **Настройки (Unit-экономика):**
  - Форма для ввода себестоимости и логистики по каждому артикулу.

### 3. Автоматизация (Future)
- Добавить интерфейс управления ставками: не только читать ставки из БД, но и отправлять изменения в WB через API (начни с `POST /adv/v0/app/bids`).
